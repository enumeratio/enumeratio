fix(wolfram): fix emit-path bugs the oracle's pre-walk hid, and two compare-side bugs

Count/Random/Thread's fixes from the last commit worked through toWolfram()
directly but not through oracle's emit(), which pre-walks every operand
into a rendered string before the outer head's SPECIAL case ever runs --
the SAME shape CycleDecomposition/Permutation already needed a raw-tree
bypass for, just reached two different ways (emit()'s own per-operand
walk for Count/Random, Equal's own per-system mapping template for
Thread). headArgs now also recognizes an already-rendered "Head[args]"
Wolfram string, which fixes Count/Random generically; Thread(Equal(...))
gets its own raw-tree bypass in emit.ts, next to CycleDecomposition/
Permutation's.

Count(collection) with no value/predicate: Wolfram's Count always needs a
pattern argument, so the 1-arg form (our own "how many" shorthand) now
emits Length instead of a Count Wolfram would leave unevaluated.

oracle/structural.ts: the Graph vertices+edges comparison checked for a
literal "Null" where Wolfram's own Null reads back through fromWolfram as
our Nothing -- fixed, and re-tested against fromWolfram() on the actual
scanned answer text rather than a hand-typed tree.

CycleDecomposition/Wolfram's own Cycles now compare equal once a fixed
point (a length-1 cycle, which Wolfram's Cycles omits and ours keeps) is
dropped from both sides.

IsPathGraph/a-cycle-is-not-a-path: classified as convention -- Wolfram's
PathGraphQ answers True for CycleGraph[4]; ours follows the textbook
definition.

Regenerated affected `in` columns via collect-forms.ts.
