# enumeratio

_enumeratio_: a counting out, an enumeration. Built on [the kernel](/nucleus/),
[the core](/aestimatio/) and [the notation](/notatio/), enumeratio gives every mathematical
object a **permanent home**: a place in a catalogue where it can be counted, found by its
index, computed from, drawn, and checked against everyone else who has written it down.

## Every object has an address

A combinatorial family is a [**collection**](/reference/collections/) — subsets,
permutations, partitions, Dyck paths, tableaux, trees — lazy and indexed, with closed-form
counts. `Count` never builds the list, and `At` unranks: the _n_-th object is computed from
_n_, so an index is an address. [Ranking and unranking](/guide/collections/) explains how.

Each family is typed by its **carrier** in the [domains](/reference/domains/), and
[**statistics**](/reference/statistics/) and [**maps**](/reference/maps/) are defined over
those carriers — evaluable on any element, and checked against FindStat by value.

## Checked, not claimed

Every entry in the [symbol reference](/reference/symbol/) crosswalks to where else the object
is written down — Wikipedia, MathWorld, the DLMF, Fungrim, the OEIS, Wolfram, Sage, and more
— and where a claim can be computed, it is: examples are tests, OEIS numbers are established
by count, identities are instantiated and evaluated, and other systems are run against ours
nightly. What we cannot yet answer is listed too, ranked, with the reason.
